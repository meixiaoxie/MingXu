# ADR-007：权限链与沙箱边界

- 状态：已批准
- 日期：2026-07-29
- 决策范围：`mingxu` 的权限、审批和隔离边界

## 背景

`mingxu` 会接触文件、网络、命令、插件和外部模型，这些动作都可能带来副作用。只靠“工具自己小心一点”是不够的，必须有统一的权限链。

## 决策

采用“两层防护”的思路：

1. **权限链**：默认 deny-first，必要时 ask，再由 approval 决定是否放行。
2. **沙箱层**：能隔离的能力尽量隔离；暂时做不到强隔离的能力，也不能假装已经隔离。

## 规则

- 任何工具、插件、MCP 或子代理，只要会产生副作用，都要经过统一权限链。
- `ask` 不是“自动允许”，而是“先停住，再等人或策略决定”。
- audit / event 不是可选装饰，而是权限链的一部分。
- 如果某个执行后端没有真正的隔离能力，就不能把它描述成“已经进入沙箱”。

## 为什么这样做

- 这样不会把安全表述写得比实现更强。
- 这样可以给后续更强的隔离方案留接口。
- 这样也方便用户理解：先判断能不能做，再判断要不要做。

## 不做的事

本 ADR 不定义具体的 UI 交互，只定义权限和隔离的架构原则。
