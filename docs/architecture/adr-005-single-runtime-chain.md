# ADR-005：唯一运行主链

- 状态：已批准
- 日期：2026-07-29
- 决策范围：`mingxu` 核心运行时的主执行路径

## 背景

当前仓库里已经出现了两套方向不同的运行链：一套偏向旧的治理式 loop，一套偏向新的 streaming loop。它们都能工作，但如果长期并存，代码会很快分裂成“谁都能跑，但谁都不确定对方是不是最新规则”的状态。

对于一个 Agent Runtime 来说，最重要的不是“有多少条能跑通的路”，而是“所有入口最后是不是都落到同一条可审计、可恢复、可验证的路上”。

## 决策

只保留一条正式主链：

```text
CLI / public API
  -> createAgentSession()
  -> AgentSession
  -> Agent
  -> runAgentLoop()
  -> ModelExecutor.stream()
  -> RuntimeStreamFn
  -> ProviderRegistry / ModelAdapter.stream()
```

## 规则

1. 所有对外入口最后都要走这一条主链。
2. `generate` 之类的兼容实现，只能在 provider 边界做适配，不能再分叉成第二套 loop。
3. 工具执行、审批、审计、会话写盘都必须挂在同一条主链上。
4. 旧实现可以在迁移期保留，但不能再作为新的默认路径。

## 为什么这样做

- 这样更容易测试，因为每个行为只需要验证一条路径。
- 这样更容易审计，因为事件和副作用都从同一个地方出来。
- 这样更容易继续重构，因为后续阶段只需要围绕一条主链改造。

## 不做的事

本 ADR 不规定每个函数的最终 TypeScript 签名，只规定架构边界和演进方向。
