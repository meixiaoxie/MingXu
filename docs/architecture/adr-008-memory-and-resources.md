# ADR-008：指令、Memory 与资源加载

- 状态：已批准
- 日期：2026-07-29
- 决策范围：`mingxu` 的指令层、长期 Memory 和资源加载

## 背景

系统里经常会把“指令”“记忆”“会话历史”混在一起，但它们其实是三件不同的事：

- 指令：告诉模型该怎么做
- Memory：记录长期偏好和可复用事实
- Session：记录某段具体对话发生过什么

如果不先分清，后面就会出现“把临时对话写成长期记忆”或者“把长期偏好塞进一次会话”的问题。

## 决策

将它们分成三条独立链路：

1. **指令加载**：Managed / User / Project / Local / Session 分层加载。
2. **长期 Memory**：单独存储、单独治理，不等于 Session。
3. **资源加载**：skills、rules、prompt 片段等按需加载，不直接把全部内容一次性塞进上下文。

## 规则

- Session 只管当前运行历史。
- Memory 只管长期可复用信息。
- 指令层级必须有稳定优先级，后层可以补充前层，但不能悄悄覆盖安全底线。
- 资源加载要受路径、大小和可见性约束。

## 为什么这样做

- 这样更容易控制上下文大小。
- 这样更容易避免信息串台。
- 这样后续做压缩和恢复时，边界会更清楚。

## 不做的事

本 ADR 不规定 Memory 的最终文件格式，只规定它和 Session、指令之间不能混用。
