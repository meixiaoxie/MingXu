# ADR-006：追加写 Session 与树状历史

- 状态：已批准
- 日期：2026-07-29
- 决策范围：`mingxu` 的正式 Session 落盘格式和恢复方式

## 背景

Session 现在承担的不只是“存几条消息”，而是要同时支持：

- 继续同一段对话
- 恢复中断运行
- 保存分支历史
- 让后续的压缩、回滚和迁移都能安全工作

如果 Session 不是追加写，而是随时覆盖整份文件，后续就很难判断哪些内容是真实历史，哪些内容是后来改出来的结果。

## 决策

正式 Session 只保留一种写法：**每个 session 一份 append-only JSONL transcript**。

关键约束：

1. 只能追加，不能原地改写历史行。
2. 通过 `parentId` 表达树状关系。
3. 一个 leaf 代表当前可继续写入的末端。
4. 旧格式只允许被迁移器读取，不再作为正式写入格式。
5. 恢复时只接受合法的最后一段截断，不能默认吞掉中间损坏数据。

## 为什么这样做

- 追加写更适合审计和恢复。
- 树状历史更适合分支、压缩和重新进入。
- 迁移时可以做到“读旧格式，写新格式”，而不是把旧格式继续拖进主链。

## 不做的事

本 ADR 不决定最终 JSON 字段的所有细节，只决定 Session 的写入原则和历史组织方式。
